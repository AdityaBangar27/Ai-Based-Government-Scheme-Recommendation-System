1. PROJECT OVERVIEW & ELEVATOR PITCH
====================================================================================================
• The Problem:
  Central and State Governments in India allocate hundreds of billions of rupees to welfare programs
  (e.g., PM Kisan, Ayushman Bharat, PM Vishwakarma, National Scholarships). However, over 60% of
  eligible citizens never apply due to lack of awareness, complex overlapping eligibility rules,
  cumbersome bureaucratic criteria, and language barriers.

• The Solution:
  An intelligent, end-to-end web portal where a citizen simply enters basic socio-economic and demographic
  details (Age, Income, Occupation, State, Category, Disability, Land status). In under 500 milliseconds,
  the system runs a hybrid recommendation engine powered by a Random Forest Classifier and rule-based
  verification, returning a personalized, ranked list of schemes with:
  - Percentage match scores (e.g., 96% Match)
  - Plain-English justifications ("Age Eligible: 18-65 yrs", "Income below threshold", "Farmer Priority")
  - Monetary and physical benefits breakdown (e.g., "₹6,000 annually", "₹5 Lakh health cover")
  - Direct links to official government application portals (.gov.in)
  - Full transparency via model accuracy and F1-score comparison charts in the UI.

• Project Scale:
  - 1,500 citizen profile training records across 16 government scheme target classes
  - 10 active operational central/state schemes
  - 7 machine learning algorithms benchmarked
  - 21 statistical exploratory plots generated
  - Zero external database dependencies (lightweight, ACID-compliant streaming CSV datastore)

5. DATA PREPROCESSING & CLEANING TECHNIQUES (STEP-BY-STEP)
====================================================================================================

The data preparation pipeline is codified in `data_analysis/03_data_preprocessing.py`:

Step 1: Ingestion & Schema Validation
  - Loaded raw CSV files with Pandas; verified data types, header alignment, and record counts.

Step 2: Missing Value Analysis & Imputation
  - Computed `df.isnull().sum()` across all features.
  - Imputation strategy implemented:
    * Numeric columns (Age, Income): Imputed using Median (robust against skewness).
    * Categorical columns (Gender, State, Category): Imputed using Mode (most frequent class).
  - Benchmark training set had 0 missing values, confirming high baseline data quality.

Step 3: Deduplication
  - Executed `df.drop_duplicates()`. Zero duplicate citizen rows found in benchmark.

Step 4: Outlier Detection & Capping (IQR Winsorization)
  - Rather than discarding citizen records (which would cause welfare exclusion bias in real life),
    we applied the Interquartile Range (IQR) Winsorization technique:
    * IQR = Q3 (75th percentile) - Q1 (25th percentile)
    * Lower Fence = Q1 - 1.5 × IQR
    * Upper Fence = Q3 + 1.5 × IQR
    * Any values outside [Lower Fence, Upper Fence] are clipped to the boundary values.
  - Applied to `Age` and `Income` features.

Step 5: Categorical Encoding
  - Fitted independent `LabelEncoder` instances for all categorical features:
    * Gender (2 classes), State (8 classes), Education (7 classes), Occupation (4 classes),
      Category (4 classes), Disability_Status (2 classes), Rural_Urban (2 classes),
      Employment_Status (4 classes).
  - Target variable `Recommended_Scheme` encoded into integer classes (0 to 15).
  - All fitted encoders serialized to `outputs/preprocessing_encoders.pkl` for test-time decoding.

Step 6: Feature Scaling
  - Fitted `StandardScaler` (z = (x - u) / s) transforming features to zero mean and unit variance.
  - Created two versions of train/test sets:
    * Raw encoded version: Fed into tree models (Random Forest, Decision Tree) which are invariant to scale.
    * Scaled version: Fed into distance/gradient models (SVM, KNN, Logistic Regression).

Step 7: Stratified Train / Test Partitioning
  - 80% Training set (1,200 samples) and 20% Held-Out Test set (300 samples).
  - `stratify=y` with `random_state=42` ensures identical class distributions in both sets,
    preventing rare schemes from being omitted in the test split.

6. FEATURE ENGINEERING & DERIVED ATTRIBUTES
====================================================================================================

Codified in `data_analysis/04_feature_engineering.py`:

1. `Is_Low_Income` (Binary Flag):
   Condition: `Income < 300,000` (₹3 Lakhs annual ceiling).
   Purpose: Directly identifies Economically Weaker Section (EWS) eligibility.

2. `Is_Youth` (Binary Flag):
   Condition: `Age <= 25`.
   Purpose: Key threshold for educational scholarships and youth skill grants.

3. `Is_Vulnerable` (Compound Intersection):
   Condition: `(Rural_Urban == 'Rural') AND (Is_Low_Income == 1)`.
   Purpose: Identifies rural impoverished families who qualify for priority agricultural subsidies.

4. `Income_Group` (Binned Quintile):
   Divided continuous income into 5 ordinal buckets: Very Low, Low, Middle, High, Very High.

5. `Age_Group` (Demographic Life Stage):
   Divided age into life stages: Child (<18), Youth (18-25), Young Adult (26-35), Adult (36-45),
   Middle Age (46-55), Senior (56-65).

6. `Income_Log` (Logarithmic Transformation):
   `np.log1p(Income)` reduces positive skewness and stabilizes variance for linear models.

Impact: Adding engineered features improved Random Forest cross-validation accuracy and reduced OOB error.

- `n_estimators = 100`       : 100 decorrelated decision trees
- `criterion = 'gini'`       : Gini impurity for split evaluation
- `max_depth = 15`           : Prevents unconstrained tree growth
- `min_samples_split = 5`    : Minimum samples required to split internal node
- `min_samples_leaf = 2`     : Minimum samples at each leaf node
- `random_state = 42`        : Reproducible training results
- `n_jobs = -1`              : Multi-threaded parallel training across all CPU cores
